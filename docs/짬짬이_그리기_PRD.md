# 짬짬이 그리기 MVP 제품 요구사항 정의서(PRD)

- **버전:** 1.0
- **형태:** 정적 웹 MVP
- **배포:** GitHub Pages

## 핵심 정의

| 항목 | 내용 |
|---|---|
| 서비스명 | 짬짬이 그리기 |
| 핵심 사용자 | 전자칠판을 사용하는 초등학교 교사 |
| 핵심 상황 | 자투리 5~10분, 비 오는 날 실내 활동, 미술 도입 |
| 핵심 가치 | 화면이 한 획씩 보여 주고, 학생은 종이에 따라 그린다. 교사는 시작만 누른다. |
| 핵심 흐름 | 그림 고르기 → 준비 → 단계별 따라 그리기 → 완성·색칠 → 마무리 |
| MVP 범위 | 그림 18개(3난이도 × 6), 자동·수동 진행, 획 강조, 교사 멘트, 오프라인 |
| 준비물 | 종이와 연필. 인쇄물·학습지 없음 |

## 1. 제품 개요

### 1.1 한 문장 정의
교사가 그림 하나를 고르면, 화면이 완성까지의 선을 한 획씩 차례로 보여 주어
학생들이 각자 종이에 따라 그릴 수 있게 하는 전자칠판용 웹서비스입니다.

### 1.2 해결하려는 문제
- 자투리 시간에 쓸 수 있는 **손으로 하는 활동**이 없습니다. 짬짬이 가족의 다섯 사이트는
  모두 화면을 터치하거나 말하는 활동이고, 종이와 연필을 쓰는 활동은 비어 있습니다.
- 따라 그리기(directed drawing)를 하려면 교사가 칠판에 직접 그려 가며 진행해야 합니다.
  이때 교사는 칠판 앞에 붙어 있어야 하고, 뒤처진 학생을 돌아볼 수 없습니다.
- 시중 자료는 완성본 그림이나 순서도 이미지여서, **한 획씩 멈춰 가며 보여 주는** 진행이
  안 됩니다. 학생은 어느 선이 새로 생긴 선인지 찾지 못합니다.
- 그림 실력에 자신이 없는 교사는 시작 자체를 꺼립니다.

### 1.3 목표

**목표 1 (최우선) — 교사가 활동을 가장 쉽게 할 수 있게 한다.**
- 홈에서 **3번 이하 클릭**으로 첫 획이 나온다.
- 시작을 누른 뒤에는 **교사 조작 0회로 끝까지** 진행된다(자동 모드가 기본).
- 교사가 교실 뒤에 있어도 **프레젠터 리모컨·키보드**로 조작된다.
- 반이 못 따라오면 **활동 중에 즉시 속도를 낮춘다.**
- 각 단계에 **교사가 그대로 읽어 주면 되는 한 문장**이 화면에 있다.
- 준비물은 종이와 연필뿐이고, 인쇄·계정·설치가 없다.

**목표 2 — 초등학생이 쉽게 그릴 수 있는 그림을 다양하게 구성한다.**
- 한 단계는 **한 획 또는 대칭 한 쌍**이다.
- 첫 획이 **크기와 위치를 정한다**(그림 전체의 40% 이상을 차지하는 큰 도형).
- **보조선을 쓰지 않는다** — 학생이 지워야 하는 선을 만들지 않는다.
- 매 단계의 누적 형태가 그 자체로 그럴듯하다.
- **비뚤어도 완성되면 그럴듯하다** — 정확한 비율을 요구하는 소재는 넣지 않는다.
- 주제 7군(동물·사람과 표정·식물·음식·사물과 탈것·계절과 행사·상상)에 걸쳐 고른다.

### 1.4 비목표
- 화면에 직접 그리게 하기 — 전자칠판 한 대에 학생 30명이므로 종이가 맞습니다.
- 잘 그렸는지 채점·판정하기.
- 작품 사진 업로드·공유·갤러리 — 아동의 얼굴과 작품은 올리지 않습니다.
- 회원가입·학급 계정·학생 이름 입력.
- 실시간 AI 그림 생성 — 오프라인 동작 원칙과 어긋납니다.
- 미술 교과 대체, 소묘·채색 기법 지도.

## 2. 사용자와 환경

### 주요 사용자
- 1차: 초등학교 교사(그림에 자신이 없는 교사를 포함)
- 2차: 초등학생 1~6학년
- 보조: 돌봄·방과후 강사

### 사용 환경
- 전자칠판, 대형 TV, 프로젝터. 교실 스피커 있음
- Chrome·Edge 등 최신 브라우저
- 학생 개인 기기·계정 없이 전체 참여
- 학교 인터넷이 끊겨도 동작해야 함(PWA)
- 학생 좌석은 화면에서 최대 8~9m 떨어져 있음

## 3. 교사 편의성 설계 (목표 1의 전개)

### 3.1 고르기 — 3번 이하 클릭
- 홈은 **완성 그림 썸네일 카드 그리드** 하나입니다. 글을 읽지 않고 그림으로 고릅니다.
- 카드에 **난이도 · 단계 수 · 예상 시간**을 적습니다(예: `쉬움 · 8단계 · 약 4분`).
  자투리 시간의 길이에 맞춰 고를 수 있어야 합니다.
- 필터는 **난이도 3개 · 주제 7개** 칩뿐입니다. 검색은 보조입니다.
- 카드를 누르면 준비 화면, 준비 화면에서 [시작]. **홈 → 카드 → 시작 = 3클릭.**

### 3.2 진행 — 시작 후 조작 0회
- **자동 모드가 기본값**입니다. 단계마다 데이터에 적힌 권장 시간이 지나면 다음 획으로
  넘어갑니다. 교사는 시작만 누르고 학생들 사이를 돌아다닐 수 있습니다.
  (짬짬이 쉼과 같은 원칙 — 시작 버튼 이후 교사는 아무것도 누르지 않는다.)
- **속도 3단**을 활동 중에 바꿉니다: 느리게(×1.5) · 보통(×1.0) · 빠르게(×0.7).
  반이 못 따라오는 것은 시작 전에 알 수 없으므로, 진행 중 변경이 반드시 가능해야 합니다.
- **수동 모드**는 화면 어디를 눌러도 다음 획입니다. 작은 버튼을 조준하게 하지 않습니다.
- **멈춤**은 한 번에 됩니다. 학생이 뒤처지면 교사가 즉시 세웁니다.

### 3.3 원격 조작 — 교실 뒤에서
프레젠터 리모컨은 대개 `PageUp`·`PageDown`을 보냅니다. 그래서 다음 키를 모두 받습니다.

| 키 | 동작 |
|---|---|
| `Space` · `→` · `PageDown` · `Enter` | 다음 획 |
| `←` · `PageUp` | 한 획 뒤로(화면만) |
| `R` | 방금 획 다시 보여 주기 |
| `P` | 자동 진행 멈춤·재개 |
| `1` `2` `3` | 느리게 · 보통 · 빠르게 |
| `C` | 완성본 잠깐 보기 |
| `F` | 전체화면 |
| `Esc` | 나가기(확인 후) |

> **뒤로 가기의 뜻을 분명히 합니다.** 학생이 이미 종이에 그린 선은 되돌릴 수 없습니다.
> 그래서 뒤로 가기의 목적은 취소가 아니라 **놓친 학생에게 다시 보여 주기**입니다.
> 교실에서 더 자주 필요한 것은 한 획 뒤로가 아니라 **방금 획 다시 재생(`R`)**이므로,
> 이쪽을 화면의 기본 버튼으로 둡니다.

### 3.4 뒤쪽 좌석에서도 보이게
- **이번 획**은 앰버 굵은 선 + 왼쪽에서 오른쪽으로 그려지는 애니메이션 + 시작점 점.
- **지난 획**은 네이비 흐린 선.
- 색만으로 구분하지 않습니다 — **굵기·색·애니메이션 세 가지를 동시에** 씁니다.
  색약 학생과 색이 뭉개지는 프로젝터를 함께 고려한 것입니다.
- 획이 그려지는 애니메이션이 **획의 시작점과 방향**을 저절로 알려 줍니다.
  화살표 기호를 따로 그리지 않아도 됩니다.
- 단계 표시(`3 / 8`)와 남은 시간을 항상 같은 자리에 둡니다.
- **단계 전환 신호음**을 냅니다(교실 스피커 전제, 기본 켜짐, 끌 수 있음).
  종이를 보고 있는 학생이 화면을 안 보고도 다음 획이 나온 것을 압니다.

### 3.5 교사 멘트
각 단계에 **읽어 주면 되는 한 문장**을 넣습니다. 교사가 그림 용어를 몰라도 진행됩니다.

- 화면에 크게 나오는 짧은 말: `큰 동그라미`
- 그 아래 교사 멘트: `종이 가운데에 주먹만큼 큰 동그라미를 그려 보세요.`

준비 화면에는 **종이 방향과 크기 안내**를 둡니다: `종이를 세로로 놓고, 가운데에 주먹만큼 크게`
— 첫 획의 크기가 그림 전체를 좌우하므로, 시작 전에 말해 주는 것이 가장 효과가 큽니다.

### 3.6 사고 방지
- 활동 중 나가기는 **확인**을 받습니다. 20분 활동이 오조작으로 사라지지 않게 합니다.
- 전자칠판이 새로고침되면 **그 단계에서 이어서** 진행합니다.
- **오프라인에서 전 기능이 동작**합니다. 학교 인터넷을 신뢰하지 않습니다.

### 3.7 마무리
- 완성 화면에 완성본을 크게 띄우고 **색칠 타이머**(기본 2분, 조절·건너뛰기 가능)를 둡니다.
- [다음 그림]으로 홈을 거치지 않고 바로 다음 활동에 들어갑니다.
- 작품은 **교사가 알아서** 합니다 — 업로드 기능을 두지 않습니다.

## 4. 그림 구성 기준 (목표 2의 전개)

### 4.1 단계 설계
| 난이도 | 대상 | 단계 수 | 획의 성격 |
|---|---|---|---|
| 쉬움 | 1~2학년 | 6~8 | 원·타원·직선 위주, 곡선 최소 |
| 보통 | 3~4학년 | 9~12 | 곡선 포함, 부분 겹침 |
| 도전 | 5~6학년 | 13~16 | 곡선·비율·겹침, 세부 표현 |

규칙:
1. **한 단계 = 한 획, 또는 대칭 한 쌍**(눈 둘·귀 둘은 한 단계로 묶습니다. 따로 떼면 어색합니다).
2. **첫 획이 크기와 위치를 정합니다.** 그림 전체 높이의 40% 이상인 큰 도형에서 시작합니다.
   작게 시작하면 종이 한구석에 몰려 완성되지 않습니다.
3. **보조선을 쓰지 않습니다.** 나중에 지워야 하는 선을 만들지 않습니다(지우개 없이 완주).
4. **누적 형태가 매 단계 그럴듯해야 합니다.** 중간에도 무엇을 그리는지 알면 학생이 안심합니다.
5. **획은 한 번에 그을 수 있는 길이**여야 합니다. 한 획이 너무 길면 손이 흔들립니다.

### 4.2 소재 선정 기준
- **비뚤어도 그럴듯한 것만** 넣습니다. 조금 어긋나면 즉시 어색해지는 소재는 넣지 않습니다.
- 얼굴·정면·단순한 실루엣이 유리하고, 측면 전신·기계 구조는 불리합니다.
- 한국 교실 맥락(김밥·눈사람·한복·우산)을 섞어 남의 자료 같지 않게 합니다.

**제외한 소재와 이유**

| 소재 | 이유 |
|---|---|
| 자전거 | 바퀴 두 개와 프레임 비율이 어긋나면 즉시 어색해집니다 |
| 손·다섯 손가락 | 손가락 길이 비율에서 거의 모두 실패합니다 |
| 달리는 네발짐승 측면 | 다리 네 개의 위치·길이를 초등학생이 맞추기 어렵습니다 |
| 국기·태극 문양 | 정확도를 요구하고, 틀린 그림을 교실 화면에 띄우는 위험이 있습니다 |
| 실존 캐릭터 | 저작권 |
| 특정 인물의 얼굴 | 초상, 그리고 닮지 않으면 실패로 느낍니다 |

### 4.3 안전 기준
무서운 형상, 폭력·무기, 종교·정치 상징, 외모를 웃음거리로 삼는 소재는 넣지 않습니다.

### 4.4 MVP 그림 18개

**쉬움 (1~2학년, 6~8단계)**
1. 고양이 얼굴 — 동물
2. 물고기 — 동물
3. 꽃 한 송이 — 식물
4. 눈사람 — 계절과 행사
5. 자동차 — 사물과 탈것
6. 웃는 얼굴 — 사람과 표정

**보통 (3~4학년, 9~12단계)**
7. 부엉이 — 동물
8. 나비 — 동물
9. 케이크 — 음식
10. 우산과 장화 — 계절과 행사
11. 로켓 — 사물과 탈것
12. 화분 선인장 — 식물

**도전 (5~6학년, 13~16단계)**
13. 코끼리 — 동물
14. 공룡 — 상상
15. 김밥과 도시락 — 음식
16. 로봇 — 사물과 탈것
17. 한복 입은 아이 — 사람과 표정
18. 고래와 파도 — 동물

### 4.5 단계 예시 — 고양이 얼굴 (쉬움 · 8단계)

| 단계 | 화면의 짧은 말 | 교사 멘트 |
|---|---|---|
| 1 | 큰 동그라미 | 종이 가운데에 주먹만큼 큰 동그라미를 그려 보세요. |
| 2 | 귀 두 개 | 동그라미 위에 세모 귀를 좌우로 하나씩 올려요. |
| 3 | 귀 안쪽 | 귀 안에 작은 세모를 하나씩 넣어요. |
| 4 | 눈 두 개 | 얼굴 가운데보다 조금 위에 동그란 눈 두 개. |
| 5 | 코 | 눈 사이 아래에 작은 세모 코. |
| 6 | 입 | 코 아래에 옆으로 누운 삼처럼 입을 그려요. |
| 7 | 수염 | 코 양쪽으로 줄 세 개씩 뻗어요. |
| 8 | 무늬 | 이마에 짧은 줄 두세 개로 무늬를 넣어요. |

## 5. 화면
1. 홈 — 그림 고르기(카드 그리드 · 난이도·주제 필터 · 즐겨찾기 · 최근 사용)
2. 준비 — 완성본 · 종이 방향과 크기 안내 · 속도 선택 · [시작]
3. 따라 그리기 — 캔버스 · 이번 획 강조 · 짧은 말과 교사 멘트 · 단계 표시 · 조작 막대
4. 완성 — 완성본 크게 · 색칠 타이머
5. 마무리 — [다음 그림] · [홈으로]

## 6. 기능 요구사항

| ID | 기능 | 우선순위 |
|---|---|---|
| FR-01 | 완성 썸네일 카드 그리드로 그림 고르기 | Must |
| FR-02 | 난이도·주제 필터 | Must |
| FR-03 | 카드에 난이도·단계 수·예상 시간 표시 | Must |

## 7. 데이터 구조

그림 하나가 파일 하나입니다(`drawings/<id>/drawing.json`).

```json
{
  "id": "cat-face",
  "title": "고양이 얼굴",
  "theme": "animal",
  "difficulty": "easy",
  "grades": ["lower"],
  "paper": "portrait",
  "viewBox": "0 0 400 500",
  "setupSay": "종이를 세로로 놓고, 가운데에 주먹만큼 크게 그릴 거예요.",
  "coloringSeconds": 120,
  "steps": [
    {
      "d": "M 120 200 A 80 80 0 1 1 280 200 A 80 80 0 1 1 120 200",
      "label": "큰 동그라미",
      "teacherSay": "종이 가운데에 주먹만큼 큰 동그라미를 그려 보세요.",
      "seconds": 25
    }
  ],
  "keywords": ["동물", "고양이", "얼굴"]
}
```

**완성본을 따로 두지 않습니다.** 완성본은 전 단계 `d`를 겹쳐 그린 것이고, 썸네일도
같은 방식으로 만듭니다. 완성본 이미지를 별도 자산으로 두면 단계를 고칠 때 어긋나는데,
합성으로 만들면 **어긋날 수 없습니다**. (짬짬이 게임에서 탭 아이콘과 헤더 로고를
한 파일로 합친 것과 같은 이유입니다.)

`단계 수`·`예상 시간`은 저장하지 않고 `steps`에서 계산합니다 — 단일 소스 원칙.

로컬에 저장하는 것은 **즐겨찾기·최근 사용·속도·소리 설정·진행 중이던 단계**뿐입니다.
학생 이름과 작품은 저장하지 않습니다.

## 8. 진행 상태
```text
HOME → READY → DRAW(1..n) → DONE → COLOR → COMPLETE
```
- `DRAW`에서 자동 진행은 `seconds × 속도배율` 뒤 다음 단계로 갑니다.
- `P`로 멈추면 타이머만 서고 화면은 그대로입니다.
- `COLOR`는 건너뛸 수 있습니다.

## 9. 검증

정적 검증(`npm test`)에서 그림 데이터를 전수 확인합니다.

- `steps` 개수가 난이도별 범위 안인지(쉬움 6~8 · 보통 9~12 · 도전 13~16)
- 각 `d`가 유효한 SVG path이고, 모든 좌표가 `viewBox` 안인지
- **첫 획의 bounding box가 그림 전체의 40% 이상인지** — 4.1의 2번 규칙을 기계로 지킵니다
- `label`·`teacherSay`가 있고 길이 제한 안인지
- `seconds`가 범위 안인지, `difficulty`·`theme`·`paper`가 허용 값인지
- `id` 중복이 없고 목록과 폴더가 일치하는지

브라우저 검증에서는 자동 진행으로 마지막 단계까지 도달하고 콘솔 오류가 0인지 봅니다.

## 10. 비기능 요구사항
- 첫 화면 2초 이내
- 오프라인에서 전 기능 동작
- 전자칠판에서 짧은 말 최소 48px, 교사 멘트 최소 32px 상당
- 선 최소 굵기와 배경 대비를 규정하고, 색만으로 정보를 전하지 않음
- 개인정보 입력 없음, 외부 요청 없음
- 키보드만으로 전 기능 조작 가능, 포커스 표시 명확
- JSON 추가만으로 그림 확장
- 최신 Chrome·Edge 우선

## 11. 기술 구성
- HTML · CSS · Vanilla JavaScript, 빌드 단계 없음
- SVG(`stroke-dasharray` 애니메이션으로 획 그리기)
- 그림 데이터 JSON + 목록 통합본 1요청
- LocalStorage, 서비스 워커(PWA)
- GitHub Pages. 서버·DB 없음

## 12. 저장소와 가족 연결

**권고: 새 저장소 `jjam-draw`.** 짬짬이 쉼·낱말과 같은 방식이고, 짬짬이 가족은 여섯이 됩니다.

- 공통 파일(`shared/jjam-switcher.js`, 웹폰트, `browser.yml`)은 **상류인 `jjam`에 먼저**
  반영하고 `npm run sync:shared`로 받습니다. 직접 고치면 동기화 검사가 깨집니다(전례 있음).
- 헤더 바로가기에 `draw`를 추가하는 작업은 **`jjam`에서 시작**해 다른 저장소로 내려갑니다.
- `favicon.svg`는 가족 공통 틀(둥근 타일 + 우상단 흰 원에 네이비 시계 배지)을 그대로 쓰고
  고유 바탕색과 심볼만 다르게 합니다. 심볼은 **연필**. 바탕색은 기존 다섯(게임 앰버 `#FFB703`
  · 퀴즈 그린 `#12A57C` · 영상 스카이 `#4FA8E8` · 이야기 퍼플 `#6145B5` · 쉼 티일 `#0E7C86`)과
  구분되는 코랄 계열을 제안하며, **어두운 테마에서 타일 경계가 묻히지 않는지 확인 후 확정**합니다.
- 이 PRD 파일은 새 저장소를 만들 때 그 저장소 루트로 옮깁니다(짬짬이 이야기 선례).

> 대안으로 `jjam` 안의 게임으로 넣으면 기존 검증·CI를 그대로 타서 더 빠릅니다. 다만
> 게임 105종 그리드에 묻히고, 자동 진행·리모컨 조작처럼 이 활동에만 필요한 조작 체계를
> 게임 공통 틀에 넣어야 해서 목표 1과 충돌합니다.

## 13. MVP 필수 범위
- 그림 18개(쉬움·보통·도전 각 6개), 주제 7군에 분산
- 홈·준비·따라 그리기·완성·마무리 5화면
- 자동 진행 + 속도 3단 + 수동 진행
- 키보드·리모컨 조작
- 획 강조와 그려지는 애니메이션
- 단계별 짧은 말과 교사 멘트
- 단계 전환 신호음, 전체화면
- 색칠 타이머
- 오프라인 실행
- 자매 사이트 바로가기

## 14. 완료 기준
- 홈에서 **3클릭 안에** 첫 획이 나온다
- 시작 후 **한 번도 누르지 않고** 마지막 단계까지 도달한다
- 활동 중 속도를 바꾸면 **다음 단계부터 즉시** 반영된다
- 프레젠터 리모컨(`PageUp`·`PageDown`)으로 앞뒤 이동이 된다
- 어느 단계에서도 **지금 그릴 획을 3초 안에 알아볼 수 있다**
- 18개 전부 마지막 단계 누적 형태가 완성본과 같다(합성이므로 구조적으로 보장)
- 쉼표 하나까지 오프라인에서 동작한다 — 인터넷을 끊고 전 과정 확인
- 새로고침 후 그 단계에서 이어진다
- 8m 뒤에서 화면의 획과 짧은 말이 읽힌다
- 전자칠판 1280·1920px에서 넘침 없음
- GitHub Pages에서 오류 없이 실행

## 15. 개발 순서
1. 그림 18개 목록과 소재 기준 확정
2. 데이터 형식과 정적 검증 스크립트 (형식을 먼저 고정)
3. 그림 1개(고양이 얼굴)로 따라 그리기 화면 완성 — 획 강조·애니메이션까지
4. 자동 진행·속도·멈춤·다시 보기·리모컨 조작
5. 홈·준비·완성·마무리 화면
6. 그림 나머지 17개 제작
7. 소리·전체화면·이어하기·즐겨찾기
8. PWA·오프라인, 가족 공통 파일 동기화, 자매 바로가기
9. 전자칠판 실화면 점검(8m 가독성·1280·1920px)
10. GitHub Pages 배포 → 교실 테스트 후 수정

## 16. 제품 원칙

> **교사는 시작만 누르고, 화면이 한 획씩 이끈다. 비뚤어도 완성되면 그럴듯하다.**

모든 기능은 `3클릭 안에 시작`, `시작 후 조작 0회`, `한 단계 한 획`, `지우개 없이 완주`
원칙을 따릅니다.
